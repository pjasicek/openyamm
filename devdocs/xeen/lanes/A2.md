## Generator interface

For A3 (`gen_quests.py`), A4 (`gen_towns.py`) and A1 (the loaders). Code: `tools/xeen/xeenlib.py` (its docstring is the
reference), driver `tools/xeen/build_world.py`.

- **Run:** `python3 tools/xeen/build_world.py` writes; `--check` compares and writes nothing (exit 1 on a
  difference); `--rows` prints the monster rows for the map lanes. Nothing is written if any check fails.
- **One writer at a time:** write mode takes an exclusive lock (`assets_dev/worlds/xeen/.build_world.lock`, flock)
  and waits for it, so two lanes' write runs never interleave (`--check` and `--rows` take none).
- **`--only <module>`** writes only the files that module adds to: the modules before it run (for the ids it reads),
  none after it; a file it shares with an earlier module (`readable_items.txt`: gen_items and gen_quests) is written
  with both modules' rows. Use it to write your own outputs while another lane's sources are mid-edit.
- **A module** is `tools/xeen/<name>.py` with one function `build(ctx)`. The driver calls them in the order
  `gen_monsters`, `gen_items`, `gen_maps`, `gen_quests`, `gen_towns` (A3's topic ids before A4's npc rows), and
  skips a module whose file does not exist yet; `--skip <module>` leaves a lane's work in progress out (its files on
  disk stay as they are). A module never writes a file; it adds rows to tables on `ctx` and returns nothing. It raises
  `xeenlib.BuildError("what is wrong, where")` for bad source data; `ctx.warn("...")` for things to report but not
  stop on.
- **Reading sources:** `ctx.load_source('towns/x1.yml')` (a path under `assets_dev/worlds/xeen/source/`;
  `required=False` returns None when missing), `ctx.maps` (the entries of `source/maps.yml`),
  `ctx.map_by_key('X1')`.
- **Writing a table:**
  `t = ctx.table('house_data.txt', sources=['towns/x1.yml'], domain='houses', engine='house_data.txt', header_rows=2)`
  then `t.add([4001, 'Vertigo Smithy', ...], origin='towns/x1.yml smithy')`.
  - `domain` is the `idRanges` key the ids must lie in; `engine` the engine table whose first `header_rows` rows are
    copied as the header and whose ids a row must not repeat (`header=[[...]]` gives the header rows directly);
    `key_column` (0) and `numeric_key` (True) say where the id is; `contribution` is the table's name in world.yml
    `tableContributions` (default: the file name without `.txt`), used to find other worlds' rows of that table.
  - Two modules asking for the same file get the same table and append to it (books: A2's items and A3's texts both
    go to `readable_items.txt`).
  - Cells are written as given (`None` empty, `True`/`False` as `x`/`-`); `xeenlib.quote_text()` quotes free text
    with commas. A row longer than the header stops the build; shorter rows are padded.
- **Other files:** `ctx.text('relations.yml', yaml_text, sources=[...])` for a file under the world root
  (`xeenlib.dump_yaml()` writes compact YAML); the generated note is `#` for YAML, `--` for `.lua`.
- **Every contributed table exists:** after the modules, the driver writes each file of
  `devdocs/xeen/lanes/TABLES.md` (`xeenlib.CONTRIBUTION_TABLES`, file names as TABLES.md: `english/quests.txt`,
  `english/autonote.txt`, `english/awards.txt`) header-only where no module filled it, so a world.yml entry never
  points at a missing file. Map-keyed tables (`house_exits`, `outdoor_travels`, `map_navigation`) are checked against
  this world's `map_stats` rows.
- **Sharing between modules:** `ctx.shared`. Filled so far: `ctx.shared['items']` (item key → id, for every row of
  `items.yml`: quest items, artifacts, bases), `ctx.shared['monsters']` (row key → id: `goblins.A`, `wobbles`),
  `ctx.shared['families']` (family key → `{picture, ids}`).
- **What every generated TSV looks like:** first line `# Generated by tools/xeen/build_world.py from <sources>; do
  not edit.`, then the engine table's header rows, then the rows, tab-separated, LF line ends. The loaders skip the
  first line as they skip every row without a numeric id (the keyed contribution composer already does; A1's new
  loaders must too). A text-keyed table (`item_sets.txt`, `outdoor_travels.txt`) has no comment line, since its
  loader would take it for a key; everything in `data_tables/` is generated anyway.
- **Checks the driver makes** (and stops on): a row id outside the domain's range, an id twice in one table, an id
  an engine table already has, an id another world already contributes to the same table, our `idRanges`
  overlapping another world's.
- **Item rows** (for A1's `tableContributions`): `items.txt` carries the standard columns 0–31 with
  `package_id` (17) `xeen`, `canonical_id` (18) `xeen:item/<key>` and `source_item_id` (19) the item id, so its
  contribution is `sourceIdColumn: 19`, `canonicalIdColumn: 18`.
