## Changes to MM6–MM9 behaviour

- **Merge point 34, shop stock (ACCEPT, right for MM6–MM8).** The code before let a shop's candidate list ignore the
  pool filter, and `generateRandomInventoryItem(Shop)` then refused the MM9 item and the slot fell back to a plain
  copy: MM6–MM8 shops were selling unenchanted MM9 Coifs and Iron Rings, which no original game and no MMerge build
  sells and which LOOT_POOL.md already said shops must not do. The fix filters the candidates
  (`HouseServiceRuntime.cpp` `generateStockItems`, `ItemGenerator::shopPoolAllows` with `lootPoolsForWorld`). Shops of
  MM6–MM8 again sell only the merged base's equipment, enchanted as before; potions, scrolls, books and reagents are
  untouched (only weapons, armour, jewellery, artifacts and relics are pooled). The setting "MM9 loot in MM6-MM8"
  still governs drops, not shops, as documented. Bought items stay and stock refreshes on the shop's own timer, so no
  migration is needed. Xeen keeping to `xeen` + `engine` whatever the setting is right for a world that borrows
  MM6–MM8's items.
- **Merge point 33, magical age (ACCEPT, right for MM6–MM9).** The originals keep magical age over rest: MM7's rest
  resets level, AC, stat and resistance bonuses only (OpenEnroth `Character::resetTempBonuses`), and the age modifier
  is cleared only by the Rejuvenation potion (OpenEnroth `Character.cpp:3287`) or an event; Divine Intervention adds
  ten years that stay. OpenYAMM wiping it on every rest made ageing monsters and Divine Intervention free. With the
  merged MMerge tables the Rejuvenation potion exists in MM6 too, so no world is left without a cure. Regression
  scenario `mm7/magical_age_survives_rest.yml` is in place.
- **Merge point 31, hidden monsters (ACCEPT, right for MM7/MM8/MM9).** The event's fourth argument (MM8's byte:
  1 = a hidden monster counts as dead, 0 = alive) is now honoured instead of always counting hidden as dead. OpenYAMM's
  MM7 events are MMMerge's MM8-format EVTs, so MM7 now behaves as in MMMerge. The probed effects are all improvements
  or neutral: Wromthrax must actually be killed for the Crusader bit (the intended quest); the Wine Cellar's leave
  check no longer credits a vampire never revealed, and its exit door (event 501) still sets the bit as in MM7
  (`D16.txt`), so play is unchanged for anyone who walks out; Smuggler's Cove's were-rats no longer go mad again after
  peace (a real bug fixed); Garrote Gorge's original completion is blocked by its hidden marker as in MM8, while
  OpenYAMM's own overlay still sets 155/158 at the last kill. The probe covered every literal call site at a first
  visit; one gap: there is no scenario holding Garrote Gorge's completion, the one place where the old and new rule
  differ and the overlay carries the quest.
- **Merge point 21, decorations the originals hide (ACCEPT).** Honouring the maps' invisible decoration flag until an
  `evt.SetSprite` shows it matches the originals (OpenEnroth skips `LEVEL_DECORATION_INVISIBLE`; MM6 `D03.txt` shows
  the six barrels with SetSprite).
- **Merge points 22, 24 and 26 (ACCEPT).** The boat menu closing on arrival, the certificate waiting for an open
  message, and the outdoor falls that skipped landing and damage are plain bug fixes with no design cost.
