## Why `build-map` moved

The old outdoor build is `EditorDocument` (`loadMapPhysicalPath`, `validate`, `buildRuntime`). Its include closure is
clean, which is what the review checked, but its link closure is not: it needs `Engine::AssetFileSystem` (PhysicsFS)
and `Engine::findSurfaceTextureLogicalSize` in `engine/ImageAssetLoader.cpp`, which reaches SDL (`SDL_LoadBMP_IO`)
and bimg to decode an image only to learn its size. Building that into `oymap` would bring SDL and bgfx into the
studio or put a second implementation of an engine function beside the first. So it follows the plan's rule (do
without until the cut lands): a fifth early cut, **G5**, is added to PLAN.md section 10a: the texture size lookup
without SDL and bimg (`readImageDimensions` in the same file already reads sizes from headers). `oymap build-map`
comes with it in S1. Nothing depends on it before S7; the 19 callers keep using the editor binary.

## The slice

`openyamm-studio/examples/gatehouse_cellars`: "The Gatehouse Cellars" (`studio01.blv`, world mm6, map_stats id 9301):
six rooms on a 64-unit grid with 64-unit walls, five openings, four doors, a lever, two chests, five spawn points,
seven lights, seven torches, an exit to New Sorpigal. Written as `project.yml`, `plan.yml` (L2), `rooms.yml`,
`objects.yml` and `wiring.yml`; `oymap build` lowers it to a GLB for the existing indoor compiler (metadata handed
over in memory), then writes `studio01.blv` (101 faces, 7 sectors), `studio01.scene.yml` and `studio01.lua`, and
`ids.lock.yml` back into the project. The build checks its own output: the game's scene reader must accept the scene
and apply it to the map, every event must be bound to a face, and rooms, openings and doors must match sectors,
portals and door records.

The game loads it from a scratch asset root (`output/studio_slice_root`, a hard-link copy of `assets_dev`, where
`oymap install` adds the three files and a `map_stats.txt` row made from Goblinwatch's). `assets_dev` is untouched.

## What the slice taught, and what changed in schema v0 because of it

- **Walls have thickness.** Two rooms an opening joins are separate outlines with a gap; the doorway (threshold,
  soffit, jambs) belongs to the `from` room and the portal sits at the far side. The door leaf stands in the middle of
  the doorway and slides into the wall. This is the Hesper kit's rule and it removed every special case from doors.
  The schema says so in `rooms.yml`'s description, and a door thicker than its wall is an error with the fix in it.
- **An opening is a relation, not coordinates:** `from`, `to`, `along` (0 to 1 on the shared stretch), `width`,
  `height`, `sill`. The build finds the facing walls. Objects are placed the same way (`room` and `offset`, or `wall`
  and `along`).
- **Edges must meet corner to corner.** Floors and ceilings get a corner at each side of every opening and wall
  pieces at each level a neighbour ends, and a face is started where its first three corners are not in a line
  (the compiler classifies a face by them).
- **Stable numbers need a lock from the first build:** sectors, events, doors, containers, face cogs and map
  variables are all in `ids.lock.yml`. A "once" switch takes a map variable of its own (`once.<event>`).
- **No silent fallbacks:** a condition the build cannot lower yet (award, stat, time ...) is an issue; a switch or
  chest without a surface is an issue (there is no asset catalogue to take a default from until S2).
- **Text that looks like a number.** The scene's 1 750-character bitset and its empty sky name were first written as
  `0` and `null`. The canonical writer now keeps a quoted scalar a string, and there is a test.
- **Themes carry texture sizes.** UVs need them and the core cannot read cooked textures yet. They move to the asset
  catalogue in S2; the field stays as an override.
- **A new map needs a `map_stats` row** and takes every column it does not set from a reference map. Monster slots
  by name need the monster tables (S1, cut G3); until then `map_stats.monsters` is in the schema but the row's
  monsters come from the reference.

Known limits of the lowering, all reported as issues rather than built wrongly: convex outlines only, flat floors,
one event per object, doors slide up or down only, chests are plain boxes, lights are not checked against the
engine's caps.

## Findings outside the slice

- **yaml-cpp nodes alias their tree.** Sorting a list of nodes rewrote the document and wrote duplicated rooms back
  to disk on the first `oymap fmt`; the non-const `operator[]` adds keys. Fixed, tested, and written into the studio
  README as rules. Anything in the core that holds `YAML::Node` values is suspect until reviewed for this.
- **WebAssembly:** Emscripten is pinned to 4.0.10 (newer libc++ fails on `std::vector<bx::Vec3>`), only bx's math is
  built, and `YAML::Emitter` must not be used (it breaks the program's exit under wasm). Details in
  `openyamm-studio/wasm/README.md`. For that reason `oymap build` does not write the compiler's `geometry.yml`
  beside its GLB.
- **The standalone build tree works:** the studio configures and builds on its own in about a minute and reuses the
  game's fetched sources, so it never waits for or disturbs `build/`.
- The first screenshot run of `run_slice.sh --shots` showed the previous build's textures once; a second run was
  right. Not explained. Look at the file times if a picture seems stale.
