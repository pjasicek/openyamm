Map Studio S5: wireframes

Companion to devdocs/map_studio/S5_BROWSER_EDITOR.md (section 3). Wireframes, not visual design: they fix what is where and what each panel shows. The styled mockups of the design page (design_page.html, revision 4) remain the visual reference; where these differ, the reason is in the document (the vocabulary that was actually built differs from the one the design page imagined).

Revision 2 (2026-11-14, after review A7, S5_REVIEW_A7.md): W1 takes pins from the game instead of a pasted loc line and keeps pins out of the map's revision; W3 addresses the part by its key; W5 shows undo as a revert entry in one append-only history; W7 (new) is the first slice, pins from the game with no browser.

W1 · Review mode (S5a): the user opens an agent's rebuild

Local mode, Goblinwatch rebuild open read-only for review. Plan and 3D side by side, selection shared. Drawer on Pins. Inspector shows the selected door as the project says it (schema form, read-only in review mode). Status bar: revision, who else is connected, the last outside change.

W2 · Author mode, indoor, Shape stage: drawing a room

Stage bar on; tool rail shows the stage's tools; tool options above the views. The drawn outline is a client-side ghost until Enter, which sends one transaction (add rooms). The plan's planned spaces show as dashed ghosts until a room with that space covers them.

W3 · Author mode, outdoor, Build stage: a building's parts and wall bays

Outdoor projects are sketch.yml. A building is structures[] of kind: building with parts (boxes, outlines, rounds) and per-wall bay lists. The bay strip editor is the one bespoke widget the outdoor Build stage needs most; everything else is the schema inspector.

W4 · Wire stage: an event, its sources and targets

Events are wiring.yml presets (door, switch, chest, exit, teleport, text, script) with condition, effects and else_effects. Selecting a source draws its links in both views; the form edits the preset; the right column is what oymap flow says the handler does after build.

W5 · A person and an agent on one project: a stale edit and its rebase

The person's transaction was made against revision A; an agent wrote revision B meanwhile. The core re-applies the person's operations on B. When they touch other objects (or their keys and test steps still hold) it lands as C without a question; otherwise the banner shows the clash and offers the two choices below. The history is append-only: an undo is an entry that reverts one earlier entry, object by object, validated like any change.

W6 · Compare with the original (rebuilds)

Driven by oymap compare --out: report, points or regions, worst places. Two 3D views with locked cameras: the original map (read from the asset root) and the rebuild (built privately). Clicking a worst place moves both cameras there.

W7 · Pins from the game (S5a slice 1, no browser)

The first slice: the user plays as today and types pin <text> in the game's console. The game writes the pin and its own screenshot into the inbox; oymap pins import files each pin into its project's pins document (its own counter and log, outside the map's revision); an agent answers through the command line with an after picture taken in the game at the same pose; the static review page shows the pair. No loc line is copied and no tour is written by hand.
