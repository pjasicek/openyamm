# Co-op multiplayer: open items

The one list of what co-op still lacks or does wrong. The design and what is built are in
[the architecture](MULTIPLAYER_LISTEN_SERVER_ARCHITECTURE.md); this file only tracks gaps.

**How to use it**

- Before starting co-op work, look here for the item. If it is here, take it and put your name or session and the
  date in its row. If it is not here and it is a gap, add it.
- When an item is done, move its row to "Closed" at the bottom with the date and where it was done (a section of the
  architecture, a scenario, a test). Do not delete rows.
- An item's id (`CO-<n>`) never changes and is never reused. Use it in commit messages.
- "Not checked" means nobody has looked whether the code already does it. Checking is a valid way to close the item.

**Slices** are those of the architecture's table: F the network, G the lobby and screens, H content and balance.
"Later" is not planned for the first version.

Last full review: 2026-11-20, after step 6 (the lobby and the screens) and the played sessions on two PCs.
