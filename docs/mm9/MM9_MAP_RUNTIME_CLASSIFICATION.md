# MM9 Map Runtime Classification

Generated by `tools/mm9_import_discovery/classify_mm9_maps.py` from local MM9 DAT v66 files.

## Scope

- DAT input directory: `mm9/extracted/WORLDS/WORLDS`
- OpenYAMM MM9 map directory checked for current exports: `assets_dev/worlds/mm9/maps`
- DAT maps scanned: `45`
- Purpose: classify MM9 maps by source DAT structure so the runtime/editor can choose the right
  representation without forcing every MM9 map into MM6-MM8 ODM/BLV assumptions.

## Classification Contract

- `outdoor_like`: terrain world models dominate, no meaningful UserPortal data; this can stay closest to
  the existing ODM-style terrain/runtime path after helper BSPs are filtered out.
- `dat_bsp_portal_like`: named `UserPortal` records plus dense `VisBSP` leaves; this should use a DAT
  BSP/portal or BLV-like sector runtime instead of plain ODM.
- `dat_bsp_like`: significant BSP leaves or portals but not clearly a terrain map; preserve DAT BSP metadata and
  route through an indoor/BSP-capable runtime path.
- `indoor_like`: not terrain-dominated and already structurally aligned with the generated BLV/BSP path.
- `needs_review`: insufficient structural signal for an automatic runtime decision.

## Implementation Implications

- Do not change the MM6-MM8 default ODM/BLV semantics for this classification. Treat these results as MM9
  import/runtime metadata.
- DAT helper models named `PhysicsBSP` and `VisBSP` must be preserved losslessly in source metadata, but should
  not leak as visible ODM faces. They are collision/visibility source structures.
- Portalized DAT maps with `UserPortal` records need a DAT BSP/portal or BLV-like runtime path for visibility,
  collision, door/portal behavior, and editor picking. Flattening them into ODM is likely both less faithful
  and less efficient.
- Outdoor-like maps can keep the ODM-compatible terrain path short term, but should still retain DAT sidecars for
  original model names, surfaces, texture flags, objects, mechanisms/events, and helper BSP metadata.
- `needs_review` maps should be opened in the editor after helper BSP filtering to decide whether they are special
  arenas/interiors or importer edge cases.
