# Dense portrait sheet experiment — 2026-09-16

**Largest tested sheet meeting the strict per-cell pixel budget: 75 portraits (15 columns × 5 rows).**
The 72-portrait tall layout and 63-portrait square layout provide more size margin.
These are density experiments, not production-approved restorations.

All requests succeeded and preserved the intended grid counts. Actual outputs contain approximately 1.573
million pixels regardless of the requested larger raster. This is an observation about these five calls,
not a documented universal limit, maximum input size, or future guarantee. Requesting 3K did not produce 3K here.

The landscape 72-cell return stretched its last row to approximately 187–188 pixels high, versus 156–159 in
previous rows. Whole-sheet scaling would miss this defect. The tight 81-cell return has six 117-pixel-wide
interiors, one pixel below the strict minimum. Boundary antialiasing has roughly one-pixel measurement
uncertainty, itself a reason not to promise minimum 2x with this layout. The 75-cell result passes with almost
no tolerance for another call; square 63 has the most sampling margin of the passing layouts.

## Packing calculation

Original bundles use 4× native references, mostly in 3×3 square-cell sheets. Tests use 2× native references
and portrait-shaped cells. This enlargement is preparation only; restoration is generated by imagegen.

Ordinary test cell: 59×79 plus two native pixels of padding on every edge = 63×83. At 2× it needs 126×166.
`floor(1,573,000 / (126 * 166)) = 75 cells` is the area bound; aspect/layout still must fit.
The 81-cell test uses two-reference-pixel gutters and 120×160 reference cells, with almost no tolerance.
No gutters would permit at most 84 portraits by area alone at this envelope; that was not generated or recommended.
Hundreds of these portraits cannot fit at actual 2× within the observed output budget.

For 2,000 targets, 75 per sheet implies a theoretical 27 calls; 72 gives 28, and 63 gives 32, versus the original
250 sheets. These estimates ignore character boundaries, partial groups, twelve 63×73 NPC portraits, failures
and retries. Keeping each 45–55-frame player family together would take roughly forty player-family calls
plus NPC work and provide more room per portrait. That complete-family layout was not separately tested.

## Visual findings

Full returned sheets and targeted native/raw comparisons were inspected. Outputs show finer continuous
contours, hair/beard rendering and shading rather than simple pixel enlargement. The two identities remain
recognizably separate; gross expressions, lowered heads, stone effects and injury frames are retained.

Size is not fidelity. Samples show altered eye/eyebrow contours, nose/jaw proportions, mouth shapes and smoother
facial treatment. The 7pc01 closed-eye face and 7pc02 injured face vary in mouth/cheek treatment across layouts;
side-angle portraits change nose/jaw contours. Subtle expression differences require individual review.
None has passed the normal three-landmark, identity-seed and final-x2 production acceptance checks. There was
no new nine-cell control call, so these tests do not establish that density alone caused the changes.

**75 is the largest tested pixel-budget pass; 63–72 is a less marginal range for further dense-sheet work.**
Keep identity families grouped. Tests intentionally place two identities in separate row blocks; they do not
establish that arbitrary identity mixing or rewriting every production bundle is safe.
