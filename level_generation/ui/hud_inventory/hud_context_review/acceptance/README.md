# HUD visual signoff: exact x2 icon scope

The user approved the HUD as presented in the context browser on 2026-09-23. This record defines that visual
signoff as the **332 exact-x2 images displayed by the browser**, including the 21 regenerated `but20`–`but26`
U/H/D states and the regenerated `manaFRM` frame. The [complete icon list](hud_icon_names.txt) has one native
filename per line. [hud_icons.csv](hud_icons.csv) gives each native canvas, displayed x2 canvas, selected PNG,
SHA-256 hash, expected runtime destination, source review status and treatment. [summary.json](summary.json)
records the counts and input hashes.

`verify.py` checked every entry against its actual native file and the frozen `expected_targets.json` contract:

- 332/332 images decode as RGBA PNGs, and both width and height are exactly twice native.
- 332/332 native file hashes, native sizes and x2 sizes match the frozen target map.
- All 332 intended `assets_dev/engine/icons_x2/*.png` destinations are unique.
- 392 browser entries currently use native fallback art; their names are in the
  [fallback list](native_fallback_names.txt). One minimap surface is generated by the game. These are outside this
  x2 acceptance list.

The x2 naming and dimensions meet the engine's restored-icon asset contract. The runtime `icons_x2` destination
directory is currently absent, so **none of these 332 PNGs is installed**. The focused restored-icon unit tests
pass and cover x2 selection, logical-size preservation and native fallback. A live game run with all 332 installed
has not been performed; this report does not claim runtime integration or canonical queue acceptance.

Three older second-pass content notes remain visible in the list despite their passing canvas checks:
`npcdwb` and `npcupb` have missing/indistinct pressed-arrow symbols, and `terra0000` has an animation transition
inconsistency. The repaired `manaFRM` is included in the signoff; its previous filled-tube candidate is not.
Canvas checks cannot resolve these art/state issues.
