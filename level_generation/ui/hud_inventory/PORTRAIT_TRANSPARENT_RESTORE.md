# Transparent player-portrait re-restoration

User direction: re-restore all collected player families using existing restored art,
with genuine transparent backgrounds. Keep complete generated artwork (not mask-only).
Provide technically sound candidates in an interactive family review UI before
asking the user for aesthetic decisions. This supersedes background-removal-only pilots.

Scope: the 73 prefixes in the data-referenced portrait-family manifest, including
non-pc prefixes. 72 have 56 native frames (4,032 targets); pc30 has 56 missing native
slots and must not be invented. Preserve usage exclusions and all historical art.

Generation: imagegen skill, built-in edits/reference-guided re-restoration, two
28-cell sheets per family (below the Dense64 cap). Supply each sheet's exact native
pose/layout guide and retained same-identity restored masters as detail references.
Reconcile old split/irregular masters into the guide's fixed 7-column / 4-row layout. This avoids
pretending that earlier provisional extractions were verified. Native reference
upscaling is preparation only and never counts as generated detail.

Compositing override: historical opaque portrait contracts remain intact as provenance;
this user-authorized run generates foreground-alpha portraits. No runtime installation
or canonical acceptance is implied by generation, technical readiness or user preference.

Technical gate: actual generated sampling strictly greater than 2 in both axes;
native canvas aspect and fixed offsets; verified frame order/count; intact partial
poses/status effects; real alpha and clean edges on light/dark/HUD material; visually
reconstructed detail at master resolution and x2 (not enlarged pixels or smoothing alone).
Nominal layout sampling is preliminary, not proof of correct facial proportions.
Record visual evidence against the exact raw hash. Never mark an automatic-only check
as technical readiness. Retain failures and repair them separately; do not stretch,
crop-to-head, recenter or upsample failures to fake passing results.

UI: searchable family list, ready/pending/held counts, native/retained/new comparison,
full master and exact-x2 previews, frame stepping/numeric diagnostic slideshow,
light/dark/checker/HUD backgrounds, like/dislike/undecided plus notes, persistent local
votes and JSON import/export bound to output hashes. User votes are preferences, not
technical/canonical approvals. Default to technically ready families; clearly separate
unfinished work. No claim of completion until every existing family has a ready result
or a concrete reported blocker. Continue from the run manifest, not old generation queues.
