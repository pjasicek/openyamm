## Tools (all in `scripts/`; venv: Python 3.14 with pymeshlab 2025.7.post1, xatlas, numpy, scipy, pillow)

- `repair.py <stem>` with `LOD_REPAIR_PYTHON=<venv python>`, `LOD_REPAIR_RUN=<name>`, `LOD_RENDER_CULL=1`. It processes
  stems in sequence and **an exception stops the rest**: run one process per stem (attachments raise "no skinned node").
- `fix_variant_maps.py <installed.glb> <out.glb> [--all] [--param <built.glb>]`: in-place far-map fixes on an
  installed GLB (variant maps; `--all` re-transfers every far map; `--param` uses the repair's `<step>.built.glb`).
  `work/param/run_one.sh <stem>` wraps it for MM9 stems.
- `build_lods.py` fixes added today: drop degenerate (welded) faces before MeshLab (they segfaulted it and forced the
  topology-preserving fallback that shredded heads); `merge_body_shadow` (mixed culling); `drop_inverted_parts`
  (inside-out closed bits that failed the winding check).
- `install_batch.sh <run> <list>` overwrites `work/<run>/install.log`; keep a copy before a second batch.

## Traps learned today

- **Identify the NPC's model before experimenting.** Appearance guesses cost hours (f8, then the dwarf women, were
  wrong). `strace -f -e trace=openat -o out.txt ./tools/run_game.sh --isolated ... --map <map>` lists the GLBs a map
  loads; then swap candidates and diff forced-LOD screenshots numerically.
- **The audit's colour score cannot see grain** (small downscaled Workbench renders): judge far textures with in-game
  forced-LOD captures, `--set debug.model_lod=N` plus a screenshot tour (`../../../tools/RUN_GAME.md`).
- Workbench audit renders draw back faces (skirt linings look like holes); use `LOD_RENDER_CULL=1`.
- The UV-correspondence tolerance (`LOD_PARAM_TOLERANCE`, default 0.02) is not what limits the UV share; gutter hits are.
