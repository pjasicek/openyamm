# LOD tooling merged (2026-11-12, lod-batch-a)

`lod_repair_claude/scripts/` now holds both options from step 1b; the fork in
`mm7_m158_lodrepair_claude/scripts/` is superseded (do not use it).

- **Curvature-weighted collapse** (`build_lods.py`): `LOD_CURVATURE_WEIGHT=<w>` (ladder `c` steps use 8),
  `LOD_CURVATURE_LEVELS=2` for LOD2 only, `LOD_CURVATURE_CAP` (8). Plain steps force weight 0.
- **Ladder** (`repair.py --ladder`, also `LOD_LADDER`): `fallback` (default) = r25_12, r30_16, r35_20, r40_25, then
  c25_12 .. c40_25 (curvature-weighted), then r45_30, c45_30; `plain` = the old four steps; or a spec
  `0.25/0.125,c0.4/0.25`. Step folders are named `r<LOD2>_<LOD3>` (plain) or `c<LOD2>_<LOD3>` (curvature).
- **`--not-worse`** (for batch reruns of models that already pass): a passing step must also score no worse than the
  installed far levels (outline + 0.5 points, colour + 1.0, LOD2 and LOD3), else the ladder goes on. `result.json`
  gets `"accepted": true|false`; if false, keep the installed GLB (`chosen` is then the step closest to the gate,
  for review only).
- **Lining fix is now the default** (`LOD_LINING_FIX=0` turns it off). Evidence (`work/lining_off/`, `work/lining_on/`,
  25/12 on mm7_m430, mm6_sor1, mm8_m472, mm7_m290): far triangles with an inward corner 5.3-8.3 % (LOD2) and
  7.4-11.8 % (LOD3) -> 0; scores equal within MeshLab noise (LOD2/LOD3 colour differences -0.3 .. +0.7); renders the
  same or slightly lighter at the hem (`work/batch_a/sheets/lining_q34.png`, `lining_crops.png`); UV share -1 point.
  On mm6_pfem it fixed the dark streaked hem.

## One model (exact command)

From `/home/pjasicek/github/OpenYAMM/level_generation/creatures/lod_repair_claude`, after claiming the model's lease
through its own project and copying the installed GLB to `../<stem>_lodrepair_claude/work/before_lodrepair/<stem>.glb`:

```sh
LOD_REPAIR_PYTHON=$PWD/venv/bin/python LOD_REPAIR_RUN=<run> LOD_RENDER_CULL=1 \
  venv/bin/python scripts/repair.py --not-worse \
  --source $PWD/../<stem>_lodrepair_claude/work/before_lodrepair/<stem>.glb <stem> > work/<run>/<stem>.out 2>&1
venv/bin/python -c "import json; r = json.load(open('work/<run>/<stem>/result.json')); print(r['chosen'], r['accepted'])"
venv/bin/python scripts/verify_far_only.py work/<run>/<stem>/installed.glb work/<run>/<stem>/<chosen>.glb
```

Then, if accepted: `check_winding.py`, `tools/install_model.py ... --world <w>`, ledger row, and the every_binding
regression per about five installs (20 s after the last install). lod-batch-a's wrappers do all of this per model:
`work/batch_a/lane.sh <stem>...` (claim, backup, ladder, install via `work/batch_a/install_one.sh`; writes
`work/batch_a/status.txt`, `LEASES.txt`); copy them and change the `batch_a` paths for your own run.

Shared layout: `mm7_m434` is a byte copy of `mm8_m560` with MM7 ramps (`mm7_m434_claude/scripts/build_glb.py`).
lod-batch-b repairs `mm8_m560`; lod-batch-a rebuilds `mm7_m434` from that install afterwards (do not claim mm7:m434).
