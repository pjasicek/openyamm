# HD master references (Claude, step 0 of every 3D creature)

This is the first step of every Claude 3D creature run, humanoid or not. Do it before any Meshy job.
The [humanoid](CLAUDE_HUMANOID_NPC_PLAYBOOK.md) and [quadruped](CLAUDE_QUADRUPED_PLAYBOOK.md) playbooks start
from its output.

## Why

The native sprites are thumbnails: a whole figure is about 260 px and a face about 25 px. The restored x2 frames are
the same picture enlarged, with no extra detail. Meshy cannot model or paint detail it never saw. Two runs show this:

- MM6 flying demon, first rebuild: the face, claws and skin came out soft at every texture size.
- MM6 bat (`mm6_bat_claude/`): Smart Topology and the retexture used x2 frames padded to 1024², and the texture came
  out blurry.

The route that worked was HD masters generated by Codex (`mm6_wdm_claude/references_hd/`).

**Never send Meshy a native sprite, a restored x2 frame or any enlargement of them**, whether as the Smart Topology
image, the multi-image views or the retexture `multiview_image_urls`. Only generated HD masters go to Meshy.

## Deliverables: five masters

Put them in `<P>/references_hd/`, one creature per image. Each is an unresized image-generation return with a
transparent background, no floor, no shadow and no text.

| File | View | Meshy use |
|---|---|---|
| `00_three_quarter.png` | front three-quarter, camera at about chest height, slightly above (shows depth) | Smart Topology `image_url` (primary; generate first) |
| `01_front.png` | front | retexture / multi-image view 1 |
| `02_back.png` | back | retexture / multi-image view 3 |
| `03_left.png` | creature's left side | retexture / multi-image view 2 |
| `04_right.png` | creature's right side | retexture / multi-image view 4 |

Retexture `multiview_image_urls` order, matching the goblin template:
`01_front`, `03_left`, `02_back`, `04_right`. Multi-image-to-3D uses the same four.

- **Canvas:** 1024×1536 portrait for upright creatures, 1536×1024 landscape for wide flyers and long quadrupeds
  (bat wingspan, wolf, serpent), so the figure fills the frame. Keep generous margins and never crop wings, tails or
  feet.
- **Pose** (the same in all five): humanoids in A-pose (arms about 35° from vertical, open separated fingers, gap
  between the legs); quadrupeds standing square with all four legs visible and the tail clear of the body; flyers with
  the wings spread as in the native front fly frame, membranes not overlapping the body.
- **Camera:** near-orthographic, even soft studio light. Keep the drama out of the light, because Meshy bakes it into
  the albedo.
- **Large heads/faces** (anything a player sees up close): also plan a head turnaround (front, three-quarter,
  profile, back; 1254², bust only), generated from the accepted body masters. See the head graft in
  `mm6_wdm_claude/README.md`.

## Inputs to Codex

1. **Authority: the ORIGINAL low-res bitmaps.** Attach the native frames that hold the identity: `mm6_<name>/native/`
   standing/fly views 0–4 (front, three-quarter front, side, three-quarter back, back), or a native five-view sheet
   such as `mm6_wdm/references/standing.png`. Add tier palette previews from `native_variants/` when the tiers
   differ. Magenta or black backgrounds are not part of the creature, so say so in the brief.
2. **Optional secondary input: one restored x2 frame,** labelled "surface material only". It never sets the design
   and is never the submission.
3. For `01`–`04`: the selected `00_three_quarter.png` as an extra input, so all five show the same creature, pose and
   proportions.

## Brief and command

Write `<P>/references_hd/CODEX_BRIEF.md`, using `mm6_wdm_claude/references_hd/CODEX_BRIEF.md` as the template. It
needs:

- **Scope.** Image generation only. Write only into `references_hd/`. No builds and no Meshy.
- **Inputs.** Each attached image with its role.
- **Deliverables.** The table above, with the canvas size.
- **Prompt content.**
  - Context: a faithful high-definition reconstruction of the existing MM6/MM7/MM8 creature as a 3D modelling
    reference, not a new design.
  - Identity: proportions, head, eyes, teeth, ears and horns, digit counts, materials and colours, all taken from
    the native frames.
  - Pose and camera.
  - A "Do NOT" list: added armour, weapons, extra limbs, colour changes, cropping.
- **Per-image checks**, which Codex re-runs before it selects a view.
- **Records.** `generation_runs.json` (id, prompt, input sha256, output path, selected flag, reason, superseded
  runs) and a `selected_views_review.png` contact sheet.

Run it from the repository root in the background (`run_in_background`). It takes 10–20 minutes; you are notified
when it exits:

```
codex exec "Follow the brief in <P>/references_hd/CODEX_BRIEF.md exactly. The attached images are its inputs in \
order. Produce the five reference images with your built-in image generation tool and save them as specified." \
  -c model_reasoning_effort=medium \
  -C /home/pjasicek/github/OpenYAMM -s workspace-write --add-dir ~/.codex/generated_images \
  -o <P>/references_hd/codex_last_message.md \
  -i <native input 1> -i <native input 2> ... \
  < /dev/null > <P>/references_hd/codex_run.log 2>&1
```

Keep the prompt before the flags, because `-i` takes several values. Codex's built-in `image_gen` needs no API key.
Pass `-c model_reasoning_effort=medium`: the default (xhigh) spent 25 minutes on five rejected drafts of one primary
for the thief. Tell Codex in the brief how to tell left from right (which side faces the image left) and to stop after
one corrective regeneration per view; once the primary passes your own gate, freeze it and generate 01–04 in a
separate run with the primary as input 1.
If `codex` is missing or image generation fails, stop and tell the user before spending any Meshy credit. Do not
fall back to sprite frames.

## Gate before Meshy

Look at every selected master next to the native frames (contact sheet at the same scale) and check:

- identity and palette;
- the digit, horn, spike and ear counts;
- the same pose and proportions in all five views;
- the side views agree with the front and back (asymmetries on the correct side);
- nothing cropped, true alpha, and the stated canvas size.

Have Codex regenerate a single failed view with one targeted correction, using `00` as input. Record the selected
files' sha256 in `creature_3d_progress.json` under `references_hd`. Only then submit Smart Topology with
`references_hd/00_three_quarter.png`.
