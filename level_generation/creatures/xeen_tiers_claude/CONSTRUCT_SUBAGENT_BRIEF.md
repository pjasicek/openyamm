# Brief: one Xeen magic construct, complete 3D creature (lane S sub-agent)

You build one new creature for the Xeen world of OpenYAMM (/home/pjasicek/github/OpenYAMM), end to end, for the
lane S parent session (owner `xeen-s2`). The user approved Meshy spending for Xeen's creatures; your Meshy limit is
given in your task (a hard ceiling; typical new creature 15-30 credits).

## Rules (all binding)
- Never `git add/commit/stash/restore/reset`; never run cmake/make/any build; no Vulkan. Binary for checks:
  `build-xeen/game/openyamm` (read-only).
- Write only inside your own project folder `level_generation/creatures/<your project>/`, plus the install that
  `tools/install_model.py --world xeen` performs (sources land in `assets_source/worlds/xeen/models/`, runtime copies in
  `assets_dev/worlds/xeen/models/`). Do NOT edit `assets_dev/worlds/xeen/models/actors.yml` (the parent merges your
  binding block) or any other lane's file. Another sub-agent works on a sibling construct in parallel: never touch its
  project.
- At most two worker processes in any analysis, with a memory cap; the disk is 95 % full: delete your own bulky scratch
  (`ls` first, literal paths) when done; keep selected artifacts.
- Game runs: `./tools/run_game.sh --isolated <unique name> --binary build-xeen/game/openyamm ...` (starts minimised),
  at most one game process of yours at a time, wait on the exact PID (`kill -0`), never `pgrep -f`; absolute
  screenshot paths.
- Codex image generation: one `codex exec` worker per image, raw returns kept (prompts, input hashes), as
  CLAUDE_HD_MASTER_REFERENCES.md says. Never send Meshy a native sprite or an enlarged/restored frame.
- Meshy only through `tools/run_creature_meshy.sh`, Blender only through `tools/run_creature_blender.sh` (headless),
  under a workspace lease: `python3 tools/creature_workspace.py claim --project <P> --identity xeen:<name> --owner
  <your owner name> --state creature_3d_progress.json --budget <limit>`; release with the token at the end.
- No stand-ins in anything you call done; report real blockers instead.

## Deliverables
- Project `level_generation/creatures/<project>/` with README (deliverables table, clips + timing + impact events,
  gates, textures and quality numbers, LOD numbers, Meshy credits by job, replay commands, known limits) and
  `creature_3d_progress.json`.
- Installed `assets_source/worlds/xeen/models/<model>.glb` (+ any attachment) via `tools/install_model.py --world xeen`,
  after `level_generation/decorations/mm8_3d/animated/scripts/check_winding.py` (0 inverted closed parts).
- At least the skin named in your task (region mask + ramp; the ramp reproduces the native look); one skin is enough
  because one tier uses the model, but the mask must cover the main colour so later Xeen tiers are possible.
- Clips: standing (hover idle), walking (hover forward), attack_melee and, where the row has a missile,
  attack_ranged with `glow`/`release` sockets; hit, dying, dead (corpse on the floor), fidget. Every clip passes the
  playbook's gates (contacts, floor rule for the corpse, jerk/smoothness, loop seams) and the floor audit:
  `python3 level_generation/creatures/claude_shared/floor/floor_audit.py --world xeen --match '<descriptor>'`
  (descriptors with a `scale_reference` crash it; audit the one without).
- LOD0-3 per the LOD playbook (`level_generation/creatures/LOD_PLAYBOOK.md`), shadow LODs.
- `integration/actors.yml`: a ready binding entry for the descriptor in your task (`actors:` list, same shape as the
  existing entries; `yaw_offset`, scale from the native sprite height vs the model, hover via the clips, `events`
  impact and sockets). The parent merges it.
- Checks before you report: the review viewer (`python3 tools/run_creature_review.py`, see `tools/CREATURE_REVIEW.md`:
  every clip and skin switch, no console errors) and textured Blender renders from the party's eye height (front,
  three-quarter, side, the blow), inspected by you. The parent merges your binding and runs the in-game check
  (headless validation and an XD-21 tour); say in your report what it should look at.
- Final message: the report the parent relays: paths, model/skin names, descriptor binding block path, clip list with
  impact times, gate numbers, texture quality numbers, Meshy credits spent (by job), known limits, anything blocked.
