## Approved technique

The method builds on [vinevi's layered minimap process](https://www.moddb.com/mods/minimaps-for-might-magic/tutorials/making-minimaps-for-might-and-magic),
with the gentler lighting and light noise selected in the
[New Sorpigal comparison](../ui/hud_inventory/minimap_study_20260927/README.md).
The numerical settings are ours, selected visually rather than recovered from the author's unavailable project.

- Exact ODM terrain and BModels; north-up orthographic projection over world XY ±32,768.
- Cycles at 2048×2048, 64 samples, denoising off. Separate terrain/object layers with terrain holdout preserving
  occlusion of buried geometry. No cast shadows.
- Northwest warm sun at 20° elevation, strength 6.6; blue world fill .40.
- Terrain normals: 85% smooth, 15% face. Geometry and heights remain unchanged.
- Terrain Random Pick: one master-pixel radius, 25% probability, 30% blend; seed 20260927.
- Building levels: black 0, white .85, gamma 1.16. Contrast 1.06, saturation 1.13, mild sharpening.
- Light monochrome terrain noise: seed 20260928; Gaussian sigma/weight bands 0/.25, 1/.50, 3/.35, 9/.15;
  normalized and clipped to ±2.5 standard deviations, strength **.06**. Open water is excluded using the unlit
  atlas color mask. This changes tone, not pixel coordinates, buildings or geometry.
- Retain a 2048×2048 composite master; perform one Lanczos resize to the native exact-x2 canvas.

[approved_recipe.json](approved_recipe.json) and [approved_noise.json](approved_noise.json) record the values.
The original New Sorpigal revision remains **byte-identical** to the reviewed light-noise image.
A new geometry revision rerenders the current ODM with that same lighting and processing recipe.

## Scope and placement

There are 15 MM6, 13 MM7 and 14 MM8 outdoor ODM maps. Indoor vector automaps and MM9's separate presentation pipeline
are outside this scope. Seven MM8 sources are 512×510, so their exports remain **1024×1020**; all others are 1024×1024.
The complete world extent maps to each existing canvas. No geometry, camera XY, placement or runtime tables change.

Tile lookup follows each world's runtime descriptor table, including MM8's master-tile remapping. Texture lookup
uses the active world, engine and other mounted packages with case-insensitive filenames. Cross-world references
are recorded explicitly; missing textures are never replaced with guessed colors. The unsampled boundary strip
uses each map's own last-row/column tiles; New Sorpigal retains its exact reviewed water margin.

The approved technique captures static terrain and BModels. Sprite vegetation, actors, animated water and dynamic
event state are absent. Repeated water texture remains visible. No imagegen was used.

## Reproduction and deployment

Before publication, from the repository root:

```sh
python3 -B level_generation/minimaps/prepare.py
/snap/bin/blender --background --factory-startup --python level_generation/minimaps/render.py
python3 -B level_generation/minimaps/finish.py
python3 -B level_generation/minimaps/validate.py
```

`finish.py --follow` processes captures during rendering; `--available` processes only completed captures.
`render.py --world mm6 --map oute3` isolates one map. Rendering resumes only when saved input hashes match.
Preparation refuses to overwrite a published revision: retain accepted files and create a new dated revision
for future edits. All five commands accept `--workspace <revision-directory>`; preparation also accepts
`--world mm6` to scope the revision. Copy the approved recipe/noise JSONs into the new workspace.
New workspaces render New Sorpigal from current geometry instead of copying the original pilot renders.
For publication, record the user request in `request.json` and finish validation and visual review first. The pilot's saved Blender scene is the fixed lighting/camera template, recorded by hash.

After the authorized visual review is recorded:

```sh
python3 -B level_generation/minimaps/publish.py --apply
python3 -B level_generation/ui/hud_inventory/deploy_icons.py --install
python3 -B level_generation/ui/hud_inventory/deploy_icons.py --check
```

For later redeployment use only the last two commands; they read the **current** accepted index and cannot silently
replay a superseded snapshot. Existing lowercase `.bmp` filenames contain PNG bytes, as in the current icon pipeline;
installed permissions are 0644. This deploys development `icons_x2`, not ZIP packages.

Minimap publication validates the frozen jobs/catalog, accepted layout revision and immutable artwork evidence,
following the deployment boundary. The generation queue separately enforces its live HUD layout input hashes.
Current minimap geometry, textures and render inputs are pinned and checked by the revision's `validation.json`.
