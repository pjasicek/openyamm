# Handoff: BModel geometry detail (shelved 2026-11-12)

**Status: experimental, shelved by the user.** The workflow and tools are kept here so the idea can be picked up again.
Nothing from this project is installed in `assets_dev`, and no shipped map uses it. Read this file first, then
[PLAYBOOK.md](PLAYBOOK.md) (rules and lessons), [README.md](README.md) (the New Sorpigal pilot) and
[LIGHTING_PROPOSAL.md](LIGHTING_PROPOSAL.md). The review page is the claude.ai artifact
https://claude.ai/artifact/SA4wRGFvmbU6uMPV52SzAg (source: `../../geometry_study_20261111/page/`).

## What was tried, in order

1. **Pilot (2026-11-11).** Seven hand-tuned New Sorpigal BModels: Armory, tavern front and hall, the bridge and the
   three parts of Goblinwatch. Each building gets an appended untouchable `<name>_geo` model. The original faces
   become Invisible but keep their collision and clicks. Relief comes from each texture's surface-material class
   map: painted timber raised, glass and doors set in. The user liked the bridge, the tavern posts and the dark
   Goblinwatch trim.
2. **Whole town, rounds 1–3.** An automatic pass over every BModel, plus trims generated by Codex from each host
   texture (eight textures, then nine more), and a review loop with an Astra reviewer (`source/astra_review.py`). The
   round-2 page section shows the result. The user called round 2 "much better".
3. **Four more towns:** Frozen Highlands (`outc1`), Free Haven (`outc2`), Silver Cove (`outd1`) and Castle Ironfist
   (`outd3`), each with concepts, re-baked originals and the automatic pass. Before relief could work, these maps
   needed about 200 new class and height maps from `level_generation/surface_materials/mat.py`.
4. **The user's verdict:** on whole towns the wins were too small for the triangles. The Free Haven stable came out
   at 4,414 triangles and looked like the original. Most triangles went into texture relief, which can't be seen at
   play distance, and 12-unit window recesses baked black.
5. **Silhouette kit** (`generate.py --kit`): eave lips with fascia and rafter ends, corner posts or corner stones,
   door frames with steps, full window frames, a footing, and openings set in only 4–6 units. A six-building
   prototype went from 20,863 to 12,214 triangles, and the eave line reads at every distance. Fixed during review:
   - lips stopping at doors, which read as separate porches;
   - lintels sticking up through the eave;
   - hip-cap stubs at the corners;
   - a blade sign cut by the lip. Notching the lip, lowering the sign and hanging it from an arm all failed. Moving
     the sign opened a hole in the wall it was set into. The fix that worked: shrink the whole roof's lip until an
     exact box test clears the sign.
6. **The kit on all of New Sorpigal** (66 models, +87k triangles). The user then found the four issues below and
   shelved the project.

## Open issues found in the last review (screenshots in `handoff/`)

- `issue_post_texture_stripes.png`: chamfered porch posts take the painted beam band of `PXSTRST` squeezed onto
  every face. The caps and bases show stripes of plaster and timber. Posts need a plain timber texture, not a band
  of a wall texture.
- `issue_door_frame_and_corner_stones.png` (magic guild): the door frame (`thcut`) encloses the whole door face,
  which is far wider than the door, so it covers the carved frieze. The corner stones stand out as separate blocks
  with gaps, and the step looks pasted on. Door frames must follow the door's painted outline (the class or height
  map), not the face. Corner stones should not be placed where a wall already has painted pilasters.
- `issue_knee_brace_gap.png` (tavern porch): the knee brace meets neither the post nor the beam, leaving visible gaps.
  `build_post` brackets need their ends snapped onto the post face and the beam soffit.
- `issue_window_frame_gaps.png` (red barn windows): the kit's jambs and head are boxes in face-texel space. They miss
  the painted frame and leave grey slivers of the 4-unit recess's side walls. Window frames must cover the recess
  edges exactly (frame inner edge = recess outline) or there must be no recess.
- From earlier: the eave lip's end sticks out where a main roof meets a lower lean-to. Frozen Highlands' round balcony
  parapet is only partly capped. The street-level tour poses often land in walls or look straight up at roofs.

The common thread: generated pieces are placed from face bounding boxes and texel rectangles, not from what is
painted. Every review found a new collision with painted or modelled detail (signs, doors, carvings, frames). A
second attempt should place each piece against the painted outline (class and height maps), and should run an
automatic collision check against the original small parts and painted features before any human review.

## Changes outside this project (kept)

- **`tools/lighting/bake_outdoor.py`:** two opt-in profile keys, both off unless a profile sets them. One is
  `model_units_per_texel` (a lightmap density per model name). The other is `clamp_rgbm`, which clamps over-range
  texels instead of failing, for review bakes. No installed map's profile sets either.
- **`assets_source/worlds/mm6/surface_materials/`** (the `assets_source` submodule): about 200 new height and class
  maps (408 files) for Frozen Highlands, Free Haven, Silver Cove and Castle Ironfist. They are the normal output of
  `level_generation/surface_materials/mat.py auto` (ledger in that folder), accepted by its checks without a human
  review, and they are not cooked into `assets_dev` yet. Cooking them gives those maps' original textures relief in
  the game, which is useful on its own; review the sheets in `level_generation/surface_materials/jobs/` first.
- **`AGENTS.md`:** a pointer to this project's playbook, now marked experimental and shelved.

## Resuming

- **Rebuild a map:** `python3 source/build.py --map <stem>` for the round-3 rules, or with `--kit all` for the
  silhouette kit. Then `python3 source/build.py --map <stem> --bake 64`.
- **Play it:** `./tools/run_game.sh --isolated <name> --assets $PWD/level_generation/projects/mm6_sorpigal_geometry_pilot/playtest/assets_dev --world mm6 --map <stem>.odm --visible --seconds 0`
  (run from the repository root).
- **Review:** `source/review.sh <stem> <run>`, then `source/astra_review.py --map <stem> review/<stem>/<run>`. For
  close-ups, use `source/kit_tour.py`, which takes shots with the HUD off.
- **Lighting:** every new face gets its own lightmap chart, so the lighting file grows 3–6 times. The user requires
  no growth. [LIGHTING_PROPOSAL.md](LIGHTING_PROPOSAL.md), option A (detail faces borrow their host face's chart, and
  small shadows come at run time), is the recommended engine change. It was never started.
